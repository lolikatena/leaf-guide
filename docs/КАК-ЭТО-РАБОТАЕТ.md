# Разбор кода

Файл для себя: что делает каждый кусок кода и что отвечать, если спросят.

---

## 1. Как приложение запускается

```
index.html  →  src/main.tsx  →  src/App.tsx  →  страница
```

1. `index.html` — единственная html-страница с пустым `<div id="root">` и шрифтами.
2. `main.tsx` находит этот div и вставляет туда приложение.
3. `App.tsx` смотрит на адрес страницы и решает, что показать.

В `main.tsx` две обёртки:

- `MantineProvider` — даёт всем компонентам Mantine нашу тему (цвета, шрифты).
- `BrowserRouter` — включает работу с адресами. Без него не работают `Routes` и `Link`.

---

## 2. Маршруты (App.tsx)

```tsx
<Route path="/" element={<Layout />}>
  <Route index element={<HomePage />} />
  <Route path="plants/:plantId" element={<PlantPage />} />
  <Route path="plants/:plantId/:diseaseId" element={<DiseasePage />} />
  <Route path="about" element={<AboutPage />} />
  <Route path="*" element={<HomePage />} />
</Route>
```

- Внешний `Route` с `Layout` — общая шапка. В `Layout.tsx` есть `<Outlet />`, туда
  роутер подставляет текущую страницу.
- `index` — страница для адреса `/`.
- `:plantId` и `:diseaseId` — части адреса, которые могут быть любыми. Для адреса
  `/plants/tomato/disease-2` получится `plantId = 'tomato'`, `diseaseId = 'disease-2'`.
- `*` — любой несуществующий адрес, показываем главную.

**Возможный вопрос:** «Почему страница не перезагружается при переходе?»
Это SPA: браузер загружает одну html-страницу, а React Router меняет адрес и
перерисовывает нужный компонент.

## 3. Данные (data/plants.ts)

Два типа:

```ts
type Disease = { id, name, description, symptoms, treatment };
type Plant = { id, name, diseases: Disease[] };
```

У каждого растения есть массив болезней. Сейчас у всех растений один и тот же массив
заглушек `placeholderDiseases`, поэтому он написан один раз и переиспользуется.

`findPlant(id)` ищет растение в массиве по `id` через `.find()`. Если не нашлось,
вернётся `undefined`.

**Возможный вопрос:** «Почему данные в коде, а не на сервере?»
Первая лабораторная — только интерфейс. Структура данных уже та, которую будет
отдавать backend, поэтому потом заменится только источник.

## 4. Страницы

### HomePage — список растений

`plants.map(...)` превращает массив растений в массив карточек. Каждая карточка — это
`Link`, ведущий на `/plants/` + id растения. `key={plant.id}` нужен React, чтобы
отличать элементы списка.

### PlantPage — болезни растения

```tsx
const { plantId } = useParams();
const plant = findPlant(plantId);
```

`useParams` достаёт `plantId` из адреса. Если растение не нашлось (например, адрес
набрали руками с ошибкой), показываем сообщение и кнопку назад. Если нашлось —
рисуем `DiseaseCard` для каждой болезни.

### DiseasePage — одна болезнь

Берёт из адреса два параметра. Сначала находит растение, потом внутри него болезнь:

```tsx
const disease = plant?.diseases.find((d) => d.id === diseaseId);
```

Знак `?.` значит «если `plant` не найден, дальше не иди и верни `undefined`» — без
него было бы падение с ошибкой.

### AboutPage — просто статичный текст.

## 5. Компоненты

- **Layout** — шапка с логотипом и навигацией. `NavLink` сам добавляет класс `active`
  ссылке открытой страницы, в CSS для неё есть подчёркивание. `end` у ссылки на `/`
  нужен, чтобы она не подсвечивалась на всех остальных страницах (ведь все адреса
  начинаются с `/`).
- **DiseaseCard** — карточка болезни. Получает через пропсы саму болезнь и id
  растения, чтобы собрать правильную ссылку «Подробнее».

**Возможный вопрос:** «Зачем выносить карточку в отдельный компонент?»
Так страница `PlantPage` остаётся короткой, а внешний вид карточки меняется в одном
месте.

## 6. Стили и тема

Цвета заданы в двух местах:

- `styles.css` — CSS-переменные `--bark`, `--leaf`, `--wound`, `--paper` для своей
  вёрстки;
- `theme.ts` — те же цвета для Mantine. Ей нужно 10 оттенков на каждый цвет, наши
  стоят на позициях 7 и 9, а `primaryShade: 7` говорит, какой считать основным.

Mantine отвечает за готовые элементы (кнопки, заголовки, текст), свой CSS — за сетку
и карточки.

Адаптивность: `grid-template-columns` делает 2 или 3 колонки, а медиазапрос
`@media (max-width: 800px)` на узком экране превращает их в одну.
