# Листочек — веб-справочник по болезням растений

Лабораторная работа №1: интерфейс приложения и каркас frontend.

## Назначение приложения

Листочек — справочник, который помогает определить болезнь растения по симптомам
поражения листьев и найти инструкцию по лечению. Пользователь выбирает растение,
видит список самых частых болезней, открывает нужную и читает симптомы и порядок
действий. Инструкции хранятся локально, в самом приложении.

Аудитория: садоводы и дачники, которые заметили на листьях пятна, налёт или
изменение цвета и хотят понять, что это и что делать.

## Пользовательские сценарии

1. **Найти болезнь по растению.** Открыть главную → выбрать растение → посмотреть
   список частых болезней.
2. **Сверить симптомы и прочитать инструкцию.** Открыть болезнь → сравнить описание
   симптомов с тем, что видно на листьях → прочитать, как лечить.
3. **Узнать о справочнике.** Открыть страницу «О справочнике».

## Экраны

| Адрес | Экран | Что делает |
|---|---|---|
| `/` | Растения | Список растений карточками |
| `/plants/:plantId` | Болезни растения | Частые болезни выбранного растения |
| `/plants/:plantId/:diseaseId` | Болезнь | Описание, симптомы и инструкция по лечению |
| `/about` | О справочнике | Назначение приложения |

## Технологии

- **React 18 + TypeScript** — основа интерфейса
- **Vite** — сборка и дев-сервер
- **React Router 6** — клиентская маршрутизация
- **Mantine 7** — библиотека UI-компонентов (заголовки, текст, кнопки)

Mantine выбрана из-за встроенной темы: цвета проекта задаются один раз в
`src/theme.ts`, и все компоненты выглядят единообразно.

## Упрощения этого этапа

- **Данные — заглушки.** Вместо настоящих болезней в карточках стоят «Болезнь 1»,
  «Описание болезни 1», «Симптомы 1». У всех растений пока одинаковый набор.
  Настоящее содержимое будет добавлено на следующих этапах.
- **Данные хранятся в коде** (`src/data/plants.ts`), а не на сервере. Структура уже
  та, которая понадобится backend: при подключении API поменяется только источник.
- **Нет поиска и фильтров** — на четырёх экранах и шести растениях они пока не нужны.
## Модель данных

Две связанные таблицы в PostgreSQL.

**plants — растения**

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | первичный ключ |
| `name` | varchar(100) | название, уникальное |

**diseases — болезни**

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | первичный ключ |
| `name` | varchar(100) | название болезни |
| `description` | text | краткое описание |
| `symptoms` | text | симптомы на листьях |
| `treatment` | text | инструкция по лечению |
| `plant_id` | integer | внешний ключ на `plants.id` |

Связь «один ко многим»: у одного растения много болезней, каждая болезнь относится к
одному растению. При удалении растения его болезни удаляются вместе с ним.

## Backend

Серверная часть лежит в папке `backend` и написана на FastAPI.

```
backend/
  app/
    main.py            приложение, подключение роутеров, CORS
    config.py          настройки из .env
    database.py        подключение к базе и сессии
    models.py          модели SQLAlchemy (таблицы)
    schemas.py         схемы Pydantic (валидация запросов и ответов)
    crud.py            операции с данными
    routers/
      plants.py        маршруты для растений
      diseases.py      маршруты для болезней
  seed.py              заполнение базы заглушками
  requirements.txt     зависимости
  .env.example         пример настроек без паролей
```

### Эндпоинты

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/plants` | список растений |
| GET | `/plants/{id}` | растение вместе с его болезнями |
| POST | `/plants` | добавить растение |
| PUT | `/plants/{id}` | изменить растение |
| DELETE | `/plants/{id}` | удалить растение и его болезни |
| GET | `/diseases` | список всех болезней |
| GET | `/diseases/{id}` | одна болезнь |
| POST | `/diseases` | добавить болезнь |
| PUT | `/diseases/{id}` | изменить болезнь |
| DELETE | `/diseases/{id}` | удалить болезнь |

Коды ответов: `200` — успех, `201` — запись создана, `204` — удалена, `400` — растение
с таким названием уже есть, `404` — запись не найдена, `422` — данные не прошли
проверку (например, пустое название).

### Настройка базы данных

1. Установить PostgreSQL и создать базу:

```bash
createdb leafguide
```

2. Скопировать пример настроек и указать свои данные:

```bash
cd backend
cp .env.example .env
```

В `.env` строка подключения:

```
DATABASE_URL=postgresql+psycopg2://пользователь:пароль@localhost:5432/leafguide
```

Файл `.env` в репозиторий не попадает, в git лежит только `.env.example` без паролей.

### Запуск backend

```bash
cd backend
python3 -m venv venv              # создать виртуальное окружение
source venv/bin/activate          # активировать (Windows: venv\Scripts\activate)
pip install -r requirements.txt   # установить зависимости
uvicorn app.main:app --reload     # запустить сервер
```

Сервер поднимется на `http://localhost:8000`, автоматическая документация с формой
для проверки запросов — на `http://localhost:8000/docs`.

Таблицы создаются сами при первом запуске. Чтобы заполнить базу заглушками:

```bash
python seed.py
```
